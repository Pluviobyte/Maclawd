# 统计页：按工具筛选

**状态**：已实现（第二节的宽度估算被实测推翻，见「二、空间约束」里的修正）
**目标位置**：原生面板「统计」页，日期区间选择条的右侧
**核心诉求**：能只看某一个工具的统计（Claude Code / Codex / Grok 等）

---

## 一、现状

### 统计页长什么样

`mac/Sources/Maclawd/AnalyticsView.swift` 的 `StatsPage`，第一行是
`rangeAndFilterBar`（`AnalyticsView.swift:93-133`）：

```
[今天][24H][7D][30D][90D] [⋯] [☰筛选图标]
└──────── 日期选择筛选 ────────┘ └ 要加的位置在这两者之间 ┘
```

- 5 个主区间胶囊 + `⋯` 溢出菜单（昨天/本周/上周/本月/今年/全部 + 自定义…）
- 最右一个漏斗图标，点开是 `AnalyticsFilterSheet`（`AnalyticsView.swift:495-536`）——
  一个 sheet 里塞了**工具、模型、项目**三个 Picker

### 关键判断：工具筛选其实已经存在，只是被藏起来了

`AnalyticsFilterSheet` 里第一个就是「工具」Picker。所以这个需求的实质不是
「加一个不存在的能力」，而是：

> **把工具筛选从三选一的 sheet 里提出来，变成区间条上一眼可见、一步可切的控件。**

理由是使用频次不对等。模型和项目筛选是偶尔的深挖动作；「只看 Codex」是每天要切
好几次的浏览动作。埋在 sheet 里意味着每次要点两下、还要先想起来它在哪。

同时这决定了一条必须遵守的约束：**同一个状态不能有两个入口**。工具提到条上之后，
sheet 里的「工具」Picker 必须删掉，只留模型和项目。两个控件写同一个
`selectedSource` 而互相不知道，是必然的 bug 来源。

### 后端已经支持，不用改

`src/runtime/analytics.js:118-121`：

```js
function selected(value, filter) {
  if (!filter || (Array.isArray(filter) && filter.length === 0)) return true;
  return Array.isArray(filter) ? filter.includes(value) : value === filter;
}
```

`src/runtime/server.js:273-287` 的 `multi()` 已经把重复的 `?source=` 收成数组。
筛选同时作用于总量、费用、趋势、热力图、分布、30 分钟明细（`design/usage-analytics.md`
「查询」一节已写明这个合同）。

**候选项来源**：`dimensions.sources`（`analytics.js:177-190`）遍历的是
`rollup.days` **全部历史**，不受当前区间限制。这是对的——切到「今天」时选项不会
突然消失，避免「昨天还能选 Grok，今天选项没了」这种看起来像 bug 的行为。

**会话时长不受影响**：`sessionsForPeriod`（`analytics.js:332`）只在
`filters.model` 存在时才返回 null。按 source 筛选时 `sessions.available` 仍为 true，
活跃时长照常显示。（模型筛选才会导致「按模型筛选时无法归属会话时长」那行提示。）

### 唯一真缺的东西：原生端没有工具显示名

`dimensions.sources` 返回的是 id：`claude-code`、`codex`、`grok`。
显示名 `SOURCE_LABELS`（`src/runtime/parsers/index.js:81-83`，由各解析器的
`export const label` 汇总）目前**只从 `/api/summary` 出**，而原生面板从来没解码过它。

后果是现在原生面板到处显示裸 id：`AnalyticsFilterSheet` 的工具 Picker、概览页的
「工具」分布块（`PanelView.swift:396`）、统计页的分布列表和 30 分钟明细，全都是
`claude-code` 而不是 `Claude Code`。Web 页因为拿了 `/api/summary` 的 `labels`，
显示是对的。

这个需求要在最显眼的位置放工具名，就不能继续显示 id。

## 二、空间约束（这是本方案的主要设计约束）

> **实施时的修正。** 下面这张表是用 `NSAttributedString.size` 按字体量的，
> 它**低估了真实排版**：SwiftUI 的 `Menu` 自带约 9pt chrome，`⋯` 菜单实际 33pt
> 而不是 24pt，五个胶囊实际 193pt 而不是 170.8pt。把整条 bar 放进
> `NSHostingView` 渲染后，padding 7 的真实结果是：
>
> | 工具名 | 条宽 | 328 内 |
> | --- | --- | --- |
> | 全部工具 | 321 | ✅ 但只剩 7pt |
> | WorkBuddy | 340 | ❌ |
> | Antigravity | 337 | ❌ |
> | GitHub Copilot | 357 | ❌ |
>
> 结论：**光靠短名不够，胶囊内边距必须从 7 降到 5**（省 20pt）。降到 5 之后
> 最宽的真实工具名还剩 12pt 余量，只有 GitHub Copilot CLI 走截断。
> 最终实现即按 `chipPadding = 5`。

面板宽度是常量 360，左右各 16 padding，**可用 328pt**。
下表是最初按字体宽度做的估算，保留以说明为什么方向（用短名）是对的、
但绝对值不可信：

| 元素 | 宽度 |
| --- | --- |
| 今天 / 24H / 7D / 30D / 90D 五个胶囊 | 170.8 |
| `⋯` 菜单 | 24 |
| 6 个 5pt 间距 | 30 |
| 漏斗图标 | 16 |
| **合计** | **≈ 240.8** |
| **剩余** | **≈ 87** |

再量工具菜单按钮（文字 + chevron 10 + padding 14）：

| 显示文字 | 按钮宽 | 87pt 内 |
| --- | --- | --- |
| 全部工具 | 65.8 | ✅ |
| Grok Build → Grok | 49.0 | ✅ |
| Codex CLI → Codex | 57.1 | ✅ |
| Claude Code → Claude | 60.5 | ✅ |
| Claude Code（全称） | 90.8 | ❌ 溢出 |
| WorkBuddy | 84.5 | ⚠️ 擦边 |
| GitHub Copilot CLI（全称） | 121.4 | ❌ 严重溢出 |

**结论：条上不能显示全称。** 必须显示短名。

短名规则（放在原生端，因为这是 360pt 面板的排版问题，不是数据问题）：

1. 去掉已知尾缀：` Code` / ` CLI` / ` Build`
   （Claude Code→Claude、Codex CLI→Codex、Grok Build→Grok、Gemini CLI→Gemini、
   Kimi Code→Kimi、Qwen Code→Qwen、Trae CLI→Trae）
2. 仍然过宽的（GitHub Copilot CLI → GitHub Copilot ≈ 106pt）：
   `.lineLimit(1) + .truncationMode(.tail) + .frame(maxWidth: 84)` 兜底
3. **全称必须在别处不丢**：菜单项、`.help()` tooltip、`accessibilityLabel` 都用全称

不采用的方案，记录理由：

- **只放图标 + 数字角标（像现有漏斗）**：筛选生效时用户看不见筛的是谁，而页面上
  所有数字都已经被它改过了。这违反产品原则 2（区分精确值/估算/缺失，不能让界面
  暗中说谎）。筛选态必须自述。
- **换行成两排**：`PanelTheme` 里那段长注释专门讲过面板高度跳动是**不可用**级别的
  缺陷。区间条高度随选中项变化会重新引入这个问题。
- **把 24H 挪进溢出菜单腾 36pt**：改动了和本需求无关的既有信息架构，留作
  实测溢出时的兜底手段，不作为首选。

## 三、交互设计

### 控件形态

区间条变成：

```
[今天][24H][7D][30D][90D] [⋯] [🔧 全部工具 ⌄] [☰]
                                └ 新增，在日期筛选右侧 ┘
```

- SwiftUI `Menu`，`.menuStyle(.borderlessButton)`，与旁边 `⋯` 同一族
- 菜单内容：`全部工具` + Divider + 各工具全称，选中项打 ✓
- **单选**。「只看 Codex」是真实诉求；「只看 Claude + Codex 两个之和」是构造出来的
  诉求。后端 `selected()` 已支持数组，将来要改多选只需把 `selectedSource: String?`
  换成 `[String]` 并改查询串拼装，不用动后端——这条路留着，但现在不修
- 未选中时按钮为次要色，选中时用 `PanelTheme.accent`，和区间胶囊的选中语言一致

### 选项列表

来自 `store.analytics.dimensions.sources`（全历史，已排序）。
只列**真正有数据**的工具——21 个解析器里大多数用户一个都没装，列出来是噪音。

### 筛选生效时的空态

现在的空态文案（`AnalyticsView.swift:67-76`）是：

> 这个区间没有数据 / 使用 AI 编程工具后，统计会随本地扫描自动更新

选了 Grok 而 Grok 这个区间没数据时，这句话是**误导**的——用户会以为扫描坏了。
必须改成：

> 当前筛选下这个区间没有数据 / 「Grok Build」在这个区间没有记录 · [清除工具筛选]

### 索引进度按工具收窄（可选精修）

`collection.sources[id]` 是**按 source** 的（`PanelModel.swift` 已解码为
`AnalyticsCollection.sources`）。选中单个工具时，「历史索引进度」应该显示该工具的
进度，而不是全局进度。否则会出现「Codex 已经索引完了，进度条却因为 Cursor 卡着而
显示 60%」这种自相矛盾的画面。

## 四、实施步骤

### 1. runtime：让 `/api/analytics` 带上工具显示名

`src/runtime/analytics.js` 的 `dimensions()` 只认识 rollup，不认识解析器注册表，
所以标签在 `server.js` 组装更合适（`SOURCE_LABELS` 那里已经 import 了）。

在 `buildAnalytics()`（`server.js:268-295`）的返回值上补一个字段：

```js
const result = queryUsageAnalytics(...);
result.dimensions.sourceLabels = Object.fromEntries(
  (result.dimensions?.sources ?? []).map((id) => [id, SOURCE_LABELS[id] ?? id]),
);
return result;
```

只加不改：`dimensions.sources` 仍是 id 数组，Web 页和现有 Swift 解码零影响。

### 2. 原生：解码标签

`mac/Sources/Maclawd/PanelModel.swift:467-475` 的 `AnalyticsDimensions`
增加 `sourceLabels: [String: String]`，并提供两个查值函数：

```swift
func label(forSource id: String) -> String      // 全称，menu / tooltip / VoiceOver 用
func shortLabel(forSource id: String) -> String // 去尾缀短名，只给区间条
```

短名规则是纯函数，好测。缺标签时回落到 id，绝不显示空白。

### 3. 原生：区间条加控件

`AnalyticsView.swift` 的 `rangeAndFilterBar`，在 `⋯` 菜单和漏斗图标之间插入
工具 Menu；`filterCount` 相应改为只数 model + project。

### 4. 原生：从 sheet 里删掉工具

`AnalyticsFilterSheet` 删掉「工具」那一行（`AnalyticsView.swift:513`）和对应的
`@State private var source`，标题改「筛选模型和项目」，漏斗的 `.help()` 从
「筛选工具、模型和项目」改成「筛选模型和项目」。

`PanelStore.applyAnalyticsFilters(source:model:project:)` 拆成两个入口：
工具菜单调 `selectTool(_:)`，sheet 调 `applyAnalyticsFilters(model:project:)`。
不要让 sheet 继续传一个它已经不再拥有的 source 值。

### 5. 原生：空态与索引进度

按第三节改空态文案 + 「清除工具筛选」按钮；索引进度在单选时读
`collection.sources[selectedSource]`。

### 6. Web 页：不动

`web/usage.html:110` 的 `fSource` 已经是工具下拉，且已经通过 `/api/summary`
的 `labels` 显示全称。这个需求在 Web 侧无事可做。

## 五、测试

沿用现有两套：`test/*.test.js`（`node --test`）+ `mac/Tests/*Contract.swift`
（由 `test/panel-*-swift.test.js` 用 swiftc 编译执行）。

| 测试 | 放哪 | 断言 |
| --- | --- | --- |
| `?source=` 单值筛出正确子集 | `test/analytics.test.js` | 已有覆盖（`analytics.test.js:60`），确认不回归 |
| `dimensions.sourceLabels` 与 id 一一对应，未知 id 回落自身 | `test/server.test.js` | 新增 |
| Swift 解码 `sourceLabels` | `mac/Tests/PanelAnalyticsContract.swift` | 新增 |
| 短名规则：三种尾缀 + 无尾缀不变 + 缺标签回落 id | 同上 | 新增 |
| 区间条渲染出工具菜单、sheet 不再含「工具」 | `test/panel-analytics-swift.test.js` 同族的源码断言 | 新增（参考 `test/panel-today-availability.test.js` 的 grep 源码风格） |

**必须人工验的一项**：第二节的宽度是算出来的，SwiftUI `Menu` 的真实内边距要以
渲染为准。实施时用 `NSHostingView` 把整条 bar 放进 328pt 容器渲染成图逐一核对，
结果推翻了估算（见第二节的修正框）。这一步顺带查出三个只有渲染才看得见的问题：

1. **`.menuStyle(.borderlessButton)` 会把自定义标签整个丢掉**——胶囊底、内边距全
   不渲染，只剩文字，而且它自己在**左侧**画一个箭头。必须改用
   `.menuStyle(.button) + .buttonStyle(.plain)`。
   （旁边现有的 `⋯` 菜单也中了同一个坑，它的胶囊底其实一直没渲染出来。
   那是既有行为，不在本次范围内，见第七节。）
2. **`.fixedSize()` 会让截断永远不触发**：文本因此拿到无约束的建议宽度，
   条被直接撑爆。
3. **`.frame(maxWidth:)` 在 Menu 标签里量不出效果**，但真正装进定宽容器后
   `lineLimit(1) + truncationMode(.tail)` 会正常截断，所以不需要它。

## 六、验收标准

1. 统计页区间条右侧有工具筛选，一次点击可切到任一有数据的工具
2. 条上始终能看出当前筛的是谁（不是只有一个角标）
3. 选中工具后：总览、趋势、热力图、分布、30 分钟明细全部同步收窄；活跃时长仍可用
4. 切区间不重置工具选择；工具选项不随区间增减
5. 筛选下的空区间给出「是筛选造成的」而非「没有数据」的解释，且能一键清除
6. 工具名显示为 `Claude Code` / `Codex CLI` 这类正式名，不出现 `claude-code`
7. 面板宽 360 不变、区间条单行不换行、面板高度不因此变化
8. sheet 里不再有工具 Picker，同一状态只有一个入口
9. `npm test` 全绿

## 七、附带发现（本方案不做，但值得单开）

**区间条上的 `⋯` 菜单一直没渲染出它的胶囊底。** 代码里写了
`.background(Capsule()...)`，但 `.menuStyle(.borderlessButton)` 会把自定义标签的
装饰整个丢弃。工具筛选改用 `.menuStyle(.button)` 之后胶囊正常显示，于是同一条上
出现了「工具筛选有底、`⋯` 没底」的不一致。修法就是同样换成 `.button`，但那会改变
既有控件的外观和宽度（本方案的全部实测数字都是在 `⋯` 无胶囊的前提下量的），
所以留到单独一次改动里做。



原生面板**所有**位置都在显示 source 裸 id：概览页「工具」分布块
（`PanelView.swift:396`）、统计页分布列表（`AnalyticsView.swift:476`）、30 分钟明细
（`AnalyticsView.swift:323`）。第 1、2 步做完后，`sourceLabels` 已经在原生端可用，
把这三处一并换成显示名是很小的增量改动，但它超出了「加一个筛选控件」的范围，
所以单独记在这里。
