# Maclawd Token 体验设计 v1

状态：设计规划，未实施。数据采集与统计合同见
[`token-tracking.md`](token-tracking.md)；本文只管**功能范围、面板呈现、与桌宠的结合**。

## 出发点：Maclawd 不是仪表盘

tokei、tokcat 都是「仪表盘 + 一个可爱图标」。Maclawd 反过来：**它首先是一个角色，
恰好知道你的用量。**

这条差别决定了后面所有取舍：

| | 仪表盘产品 | Maclawd |
| --- | --- | --- |
| 打开面板先看到 | 图表 | 角色 |
| 数字的语气 | 报表 | 角色替你记着 |
| 用量高时 | 提示你花了多少钱 | 陪你一起累 |
| 默认信息量 | 全部铺开 | 三块，其余折叠 |

tokcat 的首页文案是「你在四个月里花了 $2,513.67，而你根本不知道」——用焦虑做增长。
**Maclawd 不用这个叙事。** 它是陪伴角色，不是记账良心。这一条写进价值观红线。

## 一、Token 统计需要具备什么功能

不按「字段清单」组织，按**用户真正会问的问题**组织。每个问题对应一项能力。

### P0 — v1 必须有

| 用户会问 | 能力 | 数据来源 |
| --- | --- | --- |
| 现在在烧吗？多快？ | 实时速率 `tokens/min` | 实时 tailer |
| 今天用了多少？ | 今日 `billable` + `throughput` 双口径 | 日聚合 |
| 花在哪个项目上了？ | 按项目拆分，倒序 | 日聚合 |
| 哪个模型占大头？ | 按模型拆分，占比 | 日聚合 |
| 比平时多还是少？ | 与个人基线对比（见下） | 日聚合 |
| 缓存起作用了吗？ | 缓存命中率 | 五字段口径 |
| 今天真正工作了多久？ | 活跃时长 `activeSeconds` | 会话模型 |

**「比平时」必须用个人动态基线，不是固定阈值。** 取过去 14 天同类日的中位数。
重度用户和轻度用户看到的都应该是「相对自己」的多与少——固定阈值会让重度用户永远
看到红色，这是无意义的噪音。

### P1 — 紧随其后

| 用户会问 | 能力 |
| --- | --- |
| 我作息健康吗？ | 24 小时分布（`hours[24]`） |
| 我坚持了多少天？ | 连续活跃天数 streak |
| 最近一个月的形状？ | 30 天足迹（柱状或热力） |
| 上周对比本周？ | 7 个区间切换：今天/昨天/本周/上周/本月/今年/全部 |
| 这个月大概花了多少钱？ | 成本估算（本地价格表） |
| 单个模型的细节？ | 展开单行：输入/输出/缓存读写/命中率/单价 |

### P2 — 以后再说

- 年度回顾 Wrapped（tokei 有，做起来讨喜但不紧急）
- 预算阈值提醒
- 多设备合并（需要用户自备同步手段，与「纯本地」不冲突）
- 导出 CSV / Markdown
- 其他 AI 工具（见 `token-tracking.md` 待决事项 3）

### 明确不做

- 配额/额度百分比。需要读 Claude Desktop 的 Chromium HTTP 缓存（tokei 的做法），
  实现脆弱、随时会被上游改坏，而且与「桌宠感知活动」这条主线正交。
- 排行榜、社交比较。会把陪伴产品变成攀比产品。
- 任何上传。

## 二、前端面板如何显示

### 两个表面

**菜单栏**：常驻，一眼可见，占位极小。
**面板（popover）**：点击菜单栏展开，约 360pt 宽。

### 菜单栏

四档密度，用户可切：

```
[标记]              仅标记
[标记] 1.2M         + 今日 tokens
[标记] $3.40        + 今日成本
[标记] 12K/m        + 实时速率
```

⚠️ **这里有一个未解决的设计任务。** 菜单栏高度约 18–22px，而现有动作 QA 只覆盖
64px 与 96px 两档。45×45 viewBox 的像素角色缩到 18px 几乎不可读。tokei 正是因为
这个原因专门自绘了一枚菜单栏标记。

Maclawd 需要同样的东西：**一枚 18px 可读的简化标记**，用极少的像素表达当前状态
（例如只保留躯干轮廓 + 双眼 + 一个状态色点）。这是一个新的设计工作项，不能靠缩放
现有 SVG 解决。

标记需要能表达的状态分级（不是全部 38 个，只需要 5 档）：
`idle` / `working` / `needs_owner` / `error` / `sleeping`。

### 面板默认态

角色在最上面，数字在下面。三块可见，其余折叠。

```
┌────────────────────────────────────────┐
│                                        │
│              [ 角色 96px ]              │
│                                        │
│         正在整理工作牌 · 12K/min        │
│                                        │
├────────────────────────────────────────┤
│  今日                                   │
│                                        │
│  1.24M  非缓存读取 tokens       $3.40  │
│  比平时多 18%                           │
│                                        │
│  ▁▁▁▂▃▅▇▆▃▂▁▁▁▁▁▁▂▄▅▃▁▁▁▁            │
│  0            12            23         │
├────────────────────────────────────────┤
│  项目                                   │
│                                        │
│  Maclawd            820K       $2.10   │
│  vibe-usage         380K       $1.30   │
│  其他 3 个            40K       $0.00   │
├────────────────────────────────────────┤
│  缓存命中 78%   活跃 3h12m   连续 12 天  │
├────────────────────────────────────────┤
│  今天 ▾            更多 ⌄       设置 ⚙  │
└────────────────────────────────────────┘
```

设计要点：

1. **角色台头不是装饰。** 它播放当前状态的真实动作，下面一行是该动作的中文描述
   （复用各动作契约里已有的「一眼读法」文案）+ 实时速率。用户瞥一眼就知道
   「它在干什么」，这比任何数字都快。
2. **文案在角色下方，不在角色身上。** 主状态契约第 6 条禁止动画内出现文字，
   面板文案是面板的一部分，不违反契约。
3. **主数字只有一个口径。** 默认 `billable`，悬停显示 `throughput` 与两者差额。
   两个数字并排会让人以为其中一个是错的。
4. **对比用「比平时」，不用「比昨天」。** 昨天可能正好休息，波动没有信息量。
   对比个人 14 天中位数才有意义。
5. **24 小时稀疏柱用极简字符高度块**，不做真图表。桌宠面板要克制。
6. **项目列表最多 3 行 + 「其他 N 个」。** 完整列表在展开态。

### 面板展开态

「更多 ⌄」展开追加三块：

```
├────────────────────────────────────────┤
│  模型                                   │
│  Opus 5          880K   71%    $2.90   │
│    ↳ 输入 42K · 输出 88K                │
│      缓存读 720K · 缓存写 30K           │
│      命中 88% · $15/$75 per 1M          │
│  Sonnet 5        360K   29%    $0.50   │
├────────────────────────────────────────┤
│  最近 30 天                             │
│  ▁▂▁▃▅▂▁▁▄▇▅▃▂▁▂▅▆▄▂▁▁▃▅▇▆▄▂▁▁▂      │
├────────────────────────────────────────┤
│  作息                                   │
│  最活跃 14:00–17:00                     │
│  深夜（0–6 点）占 8%                    │
└────────────────────────────────────────┘
```

模型行点击展开单价与命中率明细（tokei v1.0.8 的做法，很实用）。

### 区间切换

`今天 ▾` 下拉：今天 / 昨天 / 本周 / 上周 / 本月 / 今年 / 全部。

切换后角色台头**不变**——角色永远显示「当前」状态，不会因为你在看上周数据就去
表演上周的状态。这一条容易做错。

### 空状态与关闭态

两种状态，同一种语气：**角色照常 idle，不消失、不显示错误图标。**
没数据不是故障，用户主动关闭更不是故障。

从未检测到 Claude Code 日志时：

```
│              [ 角色 96px ]              │
│         安静地看着你                    │
│                                        │
│  还没有找到用量记录                     │
│  Maclawd 会在你使用 Claude Code 后      │
│  自动开始记录                           │
```

用户在设置里关闭主开关后：

```
│              [ 角色 96px ]              │
│         安静地看着你                    │
│                                        │
│  用量记录已关闭                         │
│                          [ 重新开启 ]   │
```

关闭态**不显示任何历史数字**，即使数据还在盘上。用户关掉的是「记录这件事」，
在面板上继续展示旧数字会让人觉得开关没生效。重新开启后数字立刻回来（`rollup.json`
是派生数据，会全量重建）。

关闭态下菜单栏自动回落到「仅标记」档——没有数字可显示，也不该显示占位符。

### 设置面板

Token 相关设置分四项，主开关关闭时下面两项灰掉：

```
用量记录

  ☑  记录 token 用量                        默认开
     读取本机 Claude Code 日志。纯本地，不联网。

  ☑  用用量影响桌宠行为                      默认开
     累计用量会让 Maclawd 逐渐变困。

  ☐  启用 Claude Code 事件增强               默认关
     让 Maclawd 准确知道 Claude 在思考、调用工具还是
     在等你决定。需要修改 ~/.claude/settings.json。

  ☐  显示成本估算                           待决
     按 API 单价估算，与订阅费无关。

  ─────────────────────────────────────────

  [ 删除全部用量记录 ]
```

设计要点：

1. **每项都写清代价，不只写功能。** 「事件增强」必须明说要改 `~/.claude/settings.json`
   ——这是在动用户另一个工具的配置，含糊其辞会失去信任。
2. **「事件增强」默认关。** 详见 [`token-tracking.md`](token-tracking.md) 的开关分层：
   读日志可以默认开（纯只读），写别人的配置文件不行。
3. **删除是独立按钮，不挂在主开关上。** 关闭 ≠ 删除，用户可能只想暂停。删除需二次确认。
4. **关闭「事件增强」时只移除自己写入的 hook 条目**，不动用户 `settings.json` 里的
   其他任何内容。安装与卸载必须严格对称。

## 三、如何和桌宠结合

五个层次，从已定义到全新。

### 第 1 层：状态驱动（已在 token-tracking.md 定义）

Claude Code hooks → 38 个动作。这层是事件映射，已有完整表格，不重复。

### 第 2 层：强度驱动

`tokens/min` → 动画强度。三个选项（A 只选状态不改速率 / B 有界速率缩放 /
C 自由缩放）已在 `token-tracking.md` 列为待决事项，**建议 A 起步**。

### 第 3 层：体力（这层是新的，也是最有价值的）

这是 token 统计能给桌宠带来的、别的数据源给不了的东西：**角色有累积状态。**

```
energy ∈ [0, 1]
每日 0:00 重置为 1
energy = 1 − min(1, 今日 throughput ÷ 个人软上限)
个人软上限 = 过去 14 天 throughput 的中位数
```

**软上限必须是动态的个人中位数，不能硬编码。** 否则重度用户从早上九点就开始
「疲劳」，这个设定立刻变成噪音。

energy 的三个作用点，全部复用现有动作，**不需要画任何新动作**：

| 作用点 | energy 高 | energy 低 |
| --- | --- | --- |
| idle 变体权重 | Quiet Watch 为主，Claw Groom / Leg Shuffle 偶发 | Drowsy Nod 权重显著上升 |
| `away` 静默阈值 | 正常 | 缩短，更早进入 Blanket Tug → Top-down Sleep |
| 强度上限（若启用 B） | 允许上限 | 压低上限 |

runtime-lifecycle-actions.json 里 `idle.grooming` / `idle.leg_shuffle` /
`idle.drowsy` 的触发条件写的是「weighted idle scheduler」——**用 energy 偏移权重
是这个契约天然的扩展点，不需要修改契约。**

另加一条：连续高强度超过阈值后，插入一次 `idle.grooming`（Claw Groom）作为
「喘口气」。这让角色在长时间高负载里显得有生命，而不是机械循环。

**关闭后**：「用用量影响桌宠行为」关掉时，energy 恒定为 1，idle 变体权重回到
静态默认。角色仍然会在长时间静默后进入 Drowsy Nod 和 `away`，只是不再受当日
用量影响——退化后的行为必须仍然完整可用，不能出现「关了之后角色再也不睡觉」
这类空洞。

### 第 4 层：里程碑

达成时播放一次 `success`（Self High-five）：

- 单日 token 创个人新高
- 连续活跃 7 天 / 30 天
- 单日缓存命中率首次突破 90%（这个值得庆祝，说明会话组织得好）

**每天最多一次里程碑动作。** 里程碑贬值比不做更糟。

### 第 5 层：通知（极度克制）

`ambient.notification`（Attention Turn）已存在。可用于预算阈值与久坐提醒。

红线：

1. 每类通知**每天最多一次**
2. 全部可单独关闭
3. **默认全关**，由用户主动开启
4. 绝不在角色正在表演 `needs_owner` 或 `error` 时插入通知

桌宠打断人是最容易讨人嫌的行为。宁可少做。

### 交互入口

| 操作 | 行为 |
| --- | --- |
| 单击桌宠 | `interaction.click`（Poke Squish），**纯互动，不开面板** |
| 双击桌宠 | `interaction.double_click`（Surprised Hop）+ 打开面板 |
| 点击菜单栏 | 打开面板 |
| 悬停桌宠 | `interaction.hover`（Cursor Gaze） |

单击保持纯玩耍是刻意的：**桌宠首先是宠物，不是按钮。** 这和项目「角色比道具重要」
的原则一致。双击既复用了已有动作，又给了发现路径。

## 四、价值观红线

1. **不制造焦虑。** 不用「你花了多少钱而你不知道」的叙事。体力设定的语气是
   「陪你一起累」，不是「你超支了」。
2. **不在角色身上贴任何数字、进度条、百分比、徽章。** 主状态契约第 6 条。
3. **高用量不做负面表演。** 没有痛苦、生病、流汗、哭。累了就是困，困是可爱的。
4. **无数据时角色不消失。** 保持 idle，不显示错误态。
5. **不把角色变成图表的一部分。** 角色不做柱子、不做指针、不举牌子。
6. **成本永远标注为「估算」。** 本地价格表算的是 API 单价，与订阅费无关。

## 五、分阶段

与 `token-tracking.md` 的实施阶段对齐，本文只补充表现层。

| 阶段 | 表现层内容 | 依赖 |
| --- | --- | --- |
| **4a** | 在 `index.html` 里做面板原型：角色台头 + 今日 + 项目三块，数据来自阶段 1 的 `rollup.json` | 采集器 |
| **4b** | 接实时速率，验证角色台头的状态与速率同步 | 实时 tailer |
| **4c** | energy 模型接进 idle 变体权重调度器，用回放的历史数据验证 | 日聚合 |
| **5a** | 设计 18px 菜单栏标记（5 档状态），补 18px QA 尺寸档 | 设计工作项 |
| **5b** | Swift 菜单栏 + popover 接管渲染 | Mac 应用外壳 |

阶段 4 全部在浏览器里完成，可以用真实数据反复调 UI 而不碰 Swift。
