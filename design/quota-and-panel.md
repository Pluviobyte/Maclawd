## 一、要做的两件事

**都要做，不是二选一。**

| | 回答什么 | 现状 |
| --- | --- | --- |
| **用了多少** | 今天用了多少 token、花在哪个项目、哪个模型 | ✅ 采集与聚合已完成，只差面板 |
| **还有多少额度** | 5 小时窗口用了多少、什么时候重置 | ❌ 全新 |

这两个数字互相推不出来：额度只有百分比，没有项目和模型归属；
token 计数不知道订阅口径，也不知道重置时间。

## 二、额度从哪来

### 2.1 走官方接口，不读缓存 —— 已实测验证

注册 `~/.claude/settings.json` 的 `statusLine.command`。Claude Code 每次刷新状态行，
把一个 JSON 从 stdin 喂给脚本。这是官方文档化的接口
（`code.claude.com/docs/en/statusline`）。

**2026-08-03 在本机实测通过**（Claude Code v2.1.220，Max 订阅）。
真实 payload 原文存于探针目录，节选：

```json
"rate_limits": {
  "five_hour": { "used_percentage": 15, "resets_at": 1785746400 },
  "seven_day": { "used_percentage": 3,  "resets_at": 1786287600 }
}
```

字段名、类型、单位与文档完全一致。`resets_at` 是绝对 Unix 秒，换算出来的重置时刻合理
（5 小时窗口 54 分钟后重置，7 天窗口 6 天后重置）。

验证方法：用 `claude --settings <file>` 注入一个只落盘不做事的探针脚本，
**完全不碰 `~/.claude/settings.json`**。这个办法以后回归测试也能直接用。

### 2.1b 实测发现的四件事（文档上看不出来）

**1. 第一条 payload 没有 `rate_limits`。**

会话刚起来那一条只有 13 个顶层字段，`rate_limits` 整个缺席；
发生第一次 API 响应之后的那条才有（15 个字段）。文档里提了一句
「appears only after the first API response」，实测确认。

→ 采集器**必须容忍字段缺失**，不能因为第一次没读到就报错或写 0。
   没有额度数据时面板整块不显示，而不是显示 0%。

**2. `context_window` 白送，不用自己算。**

```json
"context_window": {
  "context_window_size": 1000000,
  "used_percentage": 4, "remaining_percentage": 96,
  "total_input_tokens": 35314, "total_output_tokens": 4,
  "current_usage": { "input_tokens": 3, "output_tokens": 4,
                     "cache_creation_input_tokens": 35311, "cache_read_input_tokens": 0 }
}
```

同一个通道免费给出上下文占用，连 1M 与 200K 的窗口大小都替你判好了
（本机测到 `context_window_size: 1000000`）。

→ 原计划里「上下文占用」要从 transcript 自己累加、还要维护一张 1M 模型对照表，
   **这部分工作整个删掉**。它和额度是同一次读取。

**3. `used_percentage` 冷启动时是 `null`，不是 `0`。**

第一条 payload 里 `context_window.used_percentage` 和 `remaining_percentage`
都是 `null`，`current_usage` 也是 `null`。

→ 把 `null` 当 `0` 处理会显示「上下文 0%」，那是假的。`null` 要走「暂无数据」分支。

**4. `cost.total_cost_usd` 白送。**

```json
"cost": { "total_cost_usd": 0.354, "total_duration_ms": 9581,
          "total_api_duration_ms": 5285, "total_lines_added": 0, "total_lines_removed": 0 }
```

这是 Claude Code 自己算的成本，比 Maclawd 的本地价格表估算准。
但只覆盖 Claude Code 一个来源、且只是当前会话——**不能拿来替换本地价格表**，
可以作为对照，用来校验价格表准不准。

### 2.1c 一个覆盖盲区，必须写进文档

**状态行只在交互式 TUI 里渲染。`claude -p`（print / headless 模式）不触发。**

实测：print 模式跑完一整轮，探针一次都没被调用。

→ 用户用 `claude -p` 跑的任务、CI 里跑的任务、后台 agent，**都不会更新额度**。
   这些用量真实消耗了额度，但 Maclawd 看不到那次变化，只能等下一次交互式会话刷新。

→ 面板必须诚实标注数据新鲜度（见 2.5 的「安静」态），
   不能让用户以为额度是实时的。**这条要写进设置页的说明文字。**

### 2.1d 刷新频率：比想象的低

实测约 45 秒的会话里只收到 **2 条** payload，不是持续刷。它按状态变化触发，
不是定时轮询。

→ POST 给运行时不需要重度防抖，但仍要即发即忘 + 150ms 超时（见 2.2 规则 6）。

> **为什么不用 tokei 的办法。** tokei 是去扫 Claude 桌面版的 HTTP 缓存文件：
> 找含 `organizations/` 和 `/usage` 的文件，定位 zstd 压缩魔数，解压，解析。
> 能用，但上游改一次格式就全废。`token-experience.md` 当初判断这条路脆弱是对的，
> 只是当时还不知道有官方接口。

Codex 有对应的接口，v1 先不做，但数据结构要留位置。

### 2.2 状态行只有一个坑

`statusLine` 在 settings.json 里是**单槽位**，不像 `hooks` 是按事件分组的数组。
现在的 `hook-install.js` 操作 `settings.hooks[event]`，合并天然安全；
**statusLine 直接占槽会把用户自己的状态行弄没。**

六条规则，缺一不可：

1. **已验证的 Claude HUD 自动兼容，未知状态行默认不动。** 用户只决定是否读取额度；
   检测到 Claude HUD 时自动串联并保持原显示。未知自定义状态行只显示友好提示，
   由用户显式选择「保留原显示并读取额度」。

   > 这不是假想情况。**本机就是这种情况**——`~/.claude/settings.json` 的
   > statusLine 槽位被 `claude-hud` 插件占着，命令是一条嵌套三层引号的
   > `bash -c '... awk '"'"'...'"'"' ...'`。任何试图解析或重写这条命令的做法
   > 都会失败，这正是规则 3 要用文件原样搬运的原因。
2. **串联时把原对象原样存进 `usage/statusline-chain.json`。** 不解析、不重写、不规范化。
3. **用文件传原命令，不用命令行参数。** 真实的状态行命令是任意引号的 shell 单行，
   塞进参数是引号地狱。
4. **链式子进程 3 秒硬超时。** Claude Code 亚秒级刷新且不串行化重叠调用，
   一个卡住的脚本会不断累积孤儿进程。
5. **卸载严格对称。** 只在 `statusLine.command` 仍然是我们写的那条时才恢复；
   用户中途自己改过就原样留着。
6. **脚本永远快速打印、永不抛异常。** stdout 就是用户的状态行，崩一次就是一片空白。
   POST 给运行时用 150ms 超时、即发即忘，绝不阻塞输出。

### 2.3 占了槽位就要还价值

既然占用了状态行，默认要渲染一行有用的东西：

```
Opus 5 · Maclawd · 5h 78% · 2h14m
```

串联模式下这行交给用户原来的脚本，Maclawd 只取 `rate_limits`。

### 2.4 存哪里

额度是**账号级**的，不是会话级的——会话会来会走，但「这台机器的订阅用了多少」
不属于任何一次会话。头号用例恰恰是**开工之前先看一眼**，那时根本没有会话。

- 存 `usage/account-quota.json`，与 `rollup.json` 同目录。只存百分比与重置时间戳。
- `POST /api/quota` 接收（`lan.js` 已拦掉所有非本机写请求，无需新增防护）
- `GET /api/quota` 读取，加进 `lan.js` 的只读白名单（手机镜像要能看）

### 2.5 过期的额度不是「旧」，是「错」

窗口按墙钟重置，与你干不干活无关。一个 `resetAt` 已经过去的记录会一直显示
重置前的高位——**那是在撒谎**，比没有数据更糟。

| 状态 | 判据 | 表现 |
| --- | --- | --- |
| 实时 | 5 分钟内确认过 | 正常 |
| 安静 | 超过 5 分钟没确认 | 标注「N 分钟前」 |
| 已重置 | `now > resetAt` | 变灰，不显示百分比 |
| 丢弃 | `resetAt` 过去超过 48 小时 | 删除记录 |

要分开记两个时间：`updatedAt`（数值上次变化）和 `lastSeenAt`（上次确认收到）。
只记前者的话，一个稳定不变的额度会被误判成失联。

## 三、面板

### 3.1 形态：NSPopover，不跳浏览器

点菜单栏图标、或双击桌宠 → 弹出面板。**所有内容都在面板里，不再打开 Safari。**

```swift
popover.contentViewController = NSHostingController(rootView: PanelView(...))
host.sizingOptions = .preferredContentSize     // 内容撑高度
popover.behavior = .applicationDefined         // 不自动关，自己控制
statusItem.button?.sendAction(on: [.leftMouseUp, .rightMouseUp])
```

`/usage` 网页**保留但降级**：它不再是主路径，变成「想在大屏幕上细看」的可选项，
入口挪进面板的设置页。

宽度 360pt，高度由内容决定，上限约 560pt。超过就在页面内滚动，不加宽。

### 3.2 三个页面

底部三个标签切换。

**概览（默认）**

```
┌──────────────────────────────────────┐
│                                      │
│           [ 桌宠 96px ]               │
│           正在整理工作牌               │
│           每分钟 12,400               │
├──────────────────────────────────────┤
│  额度                                 │
│  Claude 5 小时  ▓▓▓▓▓▓▓░░░  已用 78%  │
│                 2 小时 14 分后重置     │
│  Claude 本周    ▓▓▓▓▓░░░░░  已用 59%  │
│  Codex 本周     ▓▓▓░░░░░░░  已用 31%  │
├──────────────────────────────────────┤
│  今日  124 万 tokens         $3.40   │
│  比平时多 18%                          │
│  ▁▁▁▂▃▅▇▆▃▂▁▁▁▁▁▁▂▄▅▃▁▁▁            │
├──────────────────────────────────────┤
│  Maclawd            82 万             │
│  vibe-usage         38 万             │
│  其他 3 个            4 万             │
├──────────────────────────────────────┤
│      [概览]    统计     设置           │
└──────────────────────────────────────┘
```

**统计** —— 区间切换（今天/昨天/本周/上周/本月/今年/全部）、按项目 / 模型 / 工具、
30 天趋势。基本是把 `/usage` 的核心搬进来。

**设置** —— 见 3.5。

### 3.3 四条设计要点

1. **最上面是桌宠在动，不是数字。** 这是 Maclawd 和 tokei、vibe-usage 唯一的
   结构性差异——它们打开是报表，Maclawd 打开先看见角色在干活。数字排在下面。
2. **桌宠下面那行文案是独家价值。** 「正在整理工作牌」回答的是**它在干什么**，
   不是用了多少。别的用量工具给不了，因为它们没有状态引擎。
3. **额度排在 token 计数前面。** 包月用户不按 token 付费，
   「今天用了 124 万」没有决策价值；「5 小时用了 78%」直接决定现在敢不敢开大活。
4. **额度显示「已用」。** 和 Claude Code 给的口径一致（`used_percentage`），
   不做翻转。条的填充方向和百分比方向一致，不会读反。

### 3.4 三种降级态

桌宠照常 idle，**不消失、不显示错误图标**。没数据不是故障。

| 情况 | 显示 |
| --- | --- |
| 运行时没起来 | 「运行时没有启动」+ 具体报错 + 重试按钮 |
| 用量记录被关 | 「用量记录已关闭」+ 重新开启按钮，**不显示任何历史数字** |
| 从未检测到日志 | 「还没有找到用量记录」+ 说明会自动开始 |
| 额度开关没开 | 额度那一块整块不出现，不显示占位符 |

关闭态不显示历史数字，即使数据还在盘上——用户关掉的是「记录这件事」，
继续展示旧数字会让人以为开关没生效。

### 3.5 设置页

```
用量记录
  ☑  记录 token 用量                     默认开
     读取本机 AI 工具日志。纯本地，不联网。
  ☑  用用量影响桌宠行为                   默认开
  ☐  启用 Claude Code 事件增强            默认关
     写入 ~/.claude/settings.json 的 hooks（可与你已有的合并）

订阅额度
  ☐  读取订阅额度                        默认关
     自动兼容 Claude HUD 并保持原有显示；Maclawd 只在后台读取额度。
     未知自定义状态行不会被自动修改。
        ☑ Claude Code
        ☐ Codex（暂未支持）

  ☑  额度提醒                            默认开
     用到 [────●────] 85%  时提醒我
     [ 测试提醒 ]

菜单栏显示
  ○ 仅图标   ● 今日 tokens   ○ 今日成本   ○ 实时速率   ○ 额度百分比

  [ 在浏览器里打开完整统计 ]
  [ 删除全部用量记录 ]
```

**为什么「额度」是独立开关，不挂在「事件增强」下面**：hooks 是可合并的数组，
状态行需要修改 Claude Code 配置。用户完全可能愿意加 hooks 却不愿意启用额度读取。
这是两个独立的信任决定，必须分开问。

**为什么不做桌宠旁边的浮动圈**：订阅来源可能有好几个（Claude、Codex、以后还有别的），
数量不定，浮层几何撑不住。放在面板里，多几个来源就多几行，天然可扩展。

## 四、额度提醒

两个参考项目都没做这个功能——tokei 只有久坐提醒，clawd-on-desk 没有提醒。
这一块是从零设计的。

### 4.1 必须自绘浮窗，不能用系统通知

**这是最重要的一条实现约束。**

Maclawd 现在是 ad-hoc 签名（见 `PROGRESS.md`「Still not done」），没有 Developer ID。
**ad-hoc 签名的应用发系统通知，会被 macOS 静默拒掉**——不报错，就是不弹。
你会以为是代码写错了，实际是签名问题。

所以提醒必须自绘：一个无边框 `NSPanel`（`.borderless` + `.nonactivatingPanel`），
`level = .statusBar`，屏幕右上角淡入，4.5 秒后淡出。不挑签名，必弹。

拿到 Developer ID 之后可以改用系统通知，但**自绘这条路要留着**——
开发期和 ad-hoc 分发都还要靠它。

### 4.2 什么时候提醒

- 触发条件：某个窗口的**已用百分比 ≥ 用户设定的阈值**
- 默认阈值 **85%**，默认**开启**
- 阈值可调，范围 50%–95%

### 4.3 每个窗口周期最多提醒一次

**去重键是 `resetAt`，不是日期。**

5 小时窗口一天有好几个周期，每个周期都值得提醒一次；用「每天最多一次」会
漏掉后面几个周期。做法：记住已经为哪个 `resetAt` 提醒过，窗口重置后这个记录
自然失效，下一个周期重新可提醒。

### 4.4 三条克制规则

1. **桌宠正在演 `error` 或 `needs_owner` 时不插入提醒。** 那时用户已经有事要处理了。
2. **不改变桌宠的任何表演。** 额度低不让它显得累、显得慌——那是用一只宠物给人施压。
3. **可以整个关掉**，关掉后一次都不弹。

### 实机跑起来才发现的两件事

**1. 菜单栏图标会被系统折叠，popover 会飞到屏幕左边。**

这台机器的菜单栏已经挤满，系统把 Maclawd 的图标收进了溢出区（右侧那个 `‹`）。
`item.button` 仍然存在、仍然能收到点击，但屏幕位置在可见区域之外，
于是 `popover.show(relativeTo:of:)` 把面板扔到了屏幕最左边。

菜单栏挤满在真实机器上很常见（还有 Bartender / Ice 这类主动折叠的工具），
不是边缘情况。现在锚点不可用时退到桌宠身上（`PanelController.usableAnchor`）。

**2. 只有一两天数据时，「每日趋势」是一块色块而不是图表。**

一根柱子铺满整个宽度，读起来完全不像图表。现在少于 3 天不画这一块，
且柱子宽度上限 10pt。同理，值为 0 的行（`<synthetic>` 这类占位模型）不再显示。

**3. 点一下切换区间，整个面板会跳。**

最初面板高度是「跟着内容走、上限 560」。切区间会改变行数，于是面板重新布局。
加了个探针（`PanelController.startRangeProbe`，`--debug-range-probe`）把窗口框
打出来，量到的实际数字：

| 区间 | 窗口原点 | 尺寸 |
| --- | --- | --- |
| 今天 | (1126,187) | 386×633 |
| 昨天 | (1126,187) | 386×577 |
| 本月 | (1126,187) | 386×728 |
| 全部 | **(944,60)** | 386×793 |

AppKit 原点在左下，原点不变 + 高度变 = **顶边每次都在跳**，最大 151pt；
到「全部」时面板高到放不下，AppKit 把它整个搬到了另一个位置。

还有两个用户没做任何操作就会跳的来源：

- 台头那行速率**只在有速率时渲染**。桌宠从工作转到发呆就矮一行，面板自己跳。
- 菜单栏被折叠时面板锚在桌宠身上，而桌宠会自发溜达——它一挪，面板跟着滑走。

修法：**面板尺寸定成常量**（台头 152 + 内容视口 420 + 页签栏），速率行永远占位，
面板开着时不让桌宠溜达。修完探针输出只有一种尺寸：`origin=(1126,187) size=386x633`，
5 个区间 8 次采样一个像素都不动。

代价是内容短时有留白。让脚注（缓存 / 活跃 / 会话）钉在视口底部，
空白留在中间——顺带脚注变成一条固定底栏，上面行数怎么变它都不动。

**「留白不好看」和「面板乱跳」不是同一个量级的问题**：前者是审美，后者是不可用。

三条都是测试抓不到、跑起来才看得见的那类问题。第 3 条尤其说明一件事：
肉眼看不出 3pt 的漂移，得让程序把数字打出来才能确认到底修没修好。

## 七、六个会真咬人的坑

1. **系统通知不弹。** 见 4.1。这条不提前知道会浪费一整轮调试。
2. **WKWebView 默认画不透明白底。** 桌宠那块要关掉 `drawsBackground`，
   否则毛玻璃里嵌一块死白方块，看起来像渲染失败。
3. **冷启动闪白。** WKWebView 首次加载 200–400ms，必须在启动时就建好预热藏着。
4. **面板关着时 CSS 动画还在跑。** 持续耗电，关闭时要暂停。
5. **降级态不能显示 0。** `0 tokens` 的意思是「今天没用」，实际是「没测到」——这是撒谎。
6. **切换页面时高度要动画。** 直接改 `contentSize` 会「啪」地跳一下。

## 八、技术形态：混合渲染

| 区域 | 怎么画 | 为什么 |
| --- | --- | --- |
| 桌宠那一块 | WKWebView | CSS/SVG 零转换是整个架构的赌注，不能破 |
| 其余全部 | 原生 SwiftUI | 暗色、毛玻璃、系统字体、VoiceOver 全部免费 |

两个支撑事实：

- **数据管道已经现成。** `RuntimeClient.swift:249` 已经在每 2 秒轮询
  `/api/summary?range=today`，`UsageSnapshot` 里大部分字段解析好了。
  缺的 baseline、byProject、hours **接口本来就在返回**——**后端一行不用改**。
- **纯网页反而更贵。** `usage.html:9` 硬编码了 `color-scheme:light`，
  面板不支持暗色是「这不是个真 Mac 应用」最刺眼的信号，
  补一整页暗色的工作量不比写原生小。

排版会有两份实现，但**数值同源于 `/api/summary`**，漂移的只是排版。

## 九、验收标准

1. 打开面板到读懂「现在在干嘛」< 1 秒
2. 日常查看**不需要打开浏览器**
3. 冷启动到内容可见 < 150ms
4. 额度到阈值时**提醒确实弹出来了**（不是代码跑了但被系统吃掉）
5. 同一个 5 小时窗口内只提醒一次，下一个窗口重新提醒
6. 关闭用量记录后，面板不显示任何历史数字
7. 卸载额度开关后，`~/.claude/settings.json` **逐字节回到接管前**
8. 用户原有的状态行在任何情况下都没被弄坏

第 4、7、8 条必须有测试。装了卸不干净、以及提醒不弹，是这类功能最伤信任的两种失败。

**验收结果（2026-08-03）**

| | 结论 |
| --- | --- |
| 1 打开到读懂 | ✅ 概览页首屏就是角色 + 状态名 + 额度 + 今日 |
