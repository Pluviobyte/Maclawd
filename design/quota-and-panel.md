## 零、这份方案改了三件事

**1. 配额百分比从「明确不做」改成「优先做」。**

原判断的前提是「只能读 Claude Desktop 的 Chromium HTTP 缓存」——那条路确实脆弱，
结论没错。但 Claude Code 自 v2.1.80 起通过 **statusLine 协议**在 stdin 上直接给出
订阅配额，是官方文档化的接口（`code.claude.com/docs/en/statusline`）。
前提没了，结论也就不成立。

**2. 面板不是一个，是两个。**

一个零点击的贴宠配额环，一个一点击的 popover。它们回答不同的问题，
不是同一个东西的两种尺寸。

**3. 面板第一屏的数字是配额，不是 token 计数。**

对订阅用户，「今天用了 1.24M」没有决策价值——他不按 token 付费。
「5 小时窗口还剩 22%，2 小时后重置」直接决定他现在敢不敢开一个大任务。
token 计数是记账，配额是决策。桌宠面板要放的是后者。

## 一、三个正交的用量维度

这是本方案的核心论点：**这三个维度互相推不出来**，而 Maclawd 现在只有一个。

| 维度 | 用户会问 | 数据源 | 时间尺度 | 现状 |
| --- | --- | --- | --- | --- |
| **累计用量** | 我用了多少？花在哪个项目？ | 本地日志扫描（21 个工具） | 天 / 周 / 月 | ✅ 已完成 |
| **账号配额** | 还剩多少？什么时候重置？ | statusLine `rate_limits` | 5 小时 / 7 天滚动窗口 | ❌ P0 |
| **上下文占用** | 这个会话该 compact 了吗？ | transcript 累加 | 单次会话 | ❌ P2 |

为什么推不出来：

- **累计 → 配额**：推不出。订阅配额的计量口径不公开，且缓存读命中大量不计入。
- **配额 → 累计**：推不出。配额只有百分比，没有项目、模型、来源归属。
- **任何 → 上下文**：推不出。上下文是单会话瞬时值，与累计量无关。

一个已经存在的证据：`compacting` 动作早就画好了，但没有任何数据能判断
「快该 compact 了」——因为第三个维度是空的。

## 二、信息架构：四层

| 层 | 表面 | 停留时长 | **唯一**要回答的问题 | 状态 |
| --- | --- | --- | --- | --- |
| 0 | 18px 菜单栏标记 + 密度数字 | 0.2s（余光） | 它活着吗？在干活吗？ | 已有，标记待定稿 |
| 0.5 | **贴宠配额环** | **0s（零点击）** | **还能用多久？现在能开大活吗？** | **P0 新建** |
| 1 | **popover** | **3s（一瞥）** | **现在怎么样？** | **P1 新建** |
| 2 | `/usage` 网页 | 分钟级 | 让我查一下、比一下 | ✅ 已完成 |

**纪律只有一条：每层回答的问题必须不同。** 如果第 1 层和第 2 层回答同一个问题，
第 1 层就没有存在价值。

判据很实用：**任何需要停留超过 3 秒才能读懂的东西，都属于第 2 层。**
筛选器、模型明细、30 天热力图、覆盖率——全都是「分析」动作，一个都不进 popover。

## 三、配额通道（P0）

### 3.1 接口

注册 `~/.claude/settings.json` 的 `statusLine.command`。Claude Code 每次刷新状态行，
把一个 JSON 从 stdin 喂给脚本：

```
rate_limits.five_hour.used_percentage    // 0–100，已用
rate_limits.five_hour.resets_at          // 绝对 Unix 秒
rate_limits.seven_day.{used_percentage, resets_at}
model.display_name
```

脚本写到 stdout 的内容会被渲染成用户终端里的状态行。

### 3.2 单槽位安全合同

`statusLine` 是**单槽位**，不是 `hooks` 那样的事件键控 map。现有的
`hook-install.js` 全部操作 `settings.hooks[event]` 数组，合并天然安全；
**statusLine 不是，直接占槽会毁掉用户自己的状态行。**

六条硬规则，缺一不可：

1. **检测到已有 statusLine 就不接管。** 设置里显示「检测到你已有状态行，
   Maclawd 不会覆盖它」，并给一个显式的「接管并保留原有」按钮。默认什么都不做。
2. **接管时把原对象原样存进 `usage/statusline-chain.json`。** 不解析、不重写、
   不规范化——存进去什么样，恢复出来就什么样。
3. **用 sidecar 文件传原命令，不用 CLI 参数。** 真实状态行命令是任意引号的
   shell 单行，塞进参数是引号地狱。
4. **链式子进程 3 秒硬超时。** Claude Code 亚秒级刷新且不串行化重叠调用，
   一个卡住的脚本会累积孤儿进程，上限约为「超时 ÷ 刷新间隔」。
5. **卸载严格对称。** 只在 `statusLine.command` 仍然是我们写的那条时才恢复
   sidecar；用户中途自己改过就原样留着，绝不覆盖。
6. **脚本永远快速打印、永不抛异常。** stdout 就是用户的状态行，
   崩一次就是一片空白。POST 给运行时用 150ms 超时、即发即忘，绝不阻塞输出。

### 3.3 占了槽位就要还价值

既然占用了用户的状态行，默认必须渲染一行有用的东西，否则占它干什么：

```
Opus 5 · Maclawd · 5h 22% · 2h14m
```

chain 模式下这行完全交给用户的脚本，Maclawd 只虹吸 `rate_limits`。

### 3.4 存储与端点

配额是**账号级**的，不是会话级的。会话会来会走，但「这台机器的订阅用了多少」
不是会话属性——**头号用例是在开始任何工作之前先看一眼还剩多少，那时根本没有会话。**

- 存 `usage/account-quota.json`，与 `rollup.json` 同目录。只存百分比与重置时间戳，
  不存任何会话内容。
- `POST /api/quota` 接收（`lan.js` 已经拦掉所有非本机写请求，无需新增防护）
- `GET /api/quota` 读取，并加进 `lan.js` 的只读白名单（手机镜像要能看）

### 3.5 过期语义：过期的配额不是「旧」，是「错」

窗口按墙钟重置，与 CLI 活动无关。一个 `resetAt` 已过的记录会一直显示重置前的高位——
**那是在撒谎**，比没有数据更糟。

| 状态 | 判据 | 表现 |
| --- | --- | --- |
| 实时 | `lastSeenAt` 在 5 分钟内 | 正常 |
| 安静 | `lastSeenAt` 超过 5 分钟 | 标注「N 分钟前」 |
| 已重置 | `now > resetAt` | 环变灰，不显示百分比 |
| 丢弃 | `resetAt` 过去超过 48 小时 | 删除记录 |

必须分开记 `updatedAt`（值上次变化）和 `lastSeenAt`（上次确认）。只有前者的话，
一个稳定不变的配额会被误判成失联。

### 3.6 开关分层

statusLine 要写用户另一个工具的配置文件，**必须默认关**，与「事件增强」同级。
但**不能挂在「事件增强」下面**——用户可能愿意加 hooks 却不愿意让出状态行，
这是两个独立的信任决定。

```
  ☑  记录 token 用量                    默认开   纯只读
  ☐  启用 Claude Code 事件增强           默认关   写 settings.json 的 hooks（可合并）
  ☐  读取订阅配额                        默认关   占用 settings.json 的 statusLine 槽位
     Claude Code 会把 5 小时 / 7 天的配额百分比交给 Maclawd。
     状态行只有一个槽位——如果你已经有自己的状态行，Maclawd 不会碰它。
```

## 四、贴宠配额环（P0）

### 4.1 形态

一个独立的无边框透明 `NSWindow`，通过 `addChildWindow(_:ordered:)` 挂在桌宠窗口上。
子窗口关系免费搞定跟随移动、跟随显示器、跟随显隐，不需要自己同步 bounds。

```swift
// 关键属性
isOpaque = false; backgroundColor = .clear
level = petWindow.level
ignoresMouseEvents = false        // 环要能点（点开 popover）
hasShadow = false
collectionBehavior = [.canJoinAllSpaces, .stationary]
```

它不是 popover，不用点任何东西就在那儿——这是它相对 popover 的全部价值。

### 4.2 几何

```
        ┌─────────────┐
   ◔ 22%│             │
   5h    │   桌宠      │
   ◕ 41%│             │
   7d    └─────────────┘
```

- 两枚**独立**的环，不做同心双环。
- 环 24px，读数栏 40px（两行：百分比 / 窗口名），环距 8，
  整簇约 72 × 60pt。
- 贴在角色 `marginBox` 的**左侧**，与角色留 8pt 间隙；左边不够才翻到右侧。
  留左侧是因为权限气泡从右侧进入，两者不能打架。
- 贴不下时（角色贴在屏幕左边缘）翻右侧；两侧都不够就整簇隐藏，不做压缩变形。

> **为什么不抄同心双环。** 参考实现把 5 小时和 7 天压进一枚环的内外圈，
> 是因为它要支持三个 provider × 最多 12 台机器，环的数量会爆炸。
> Maclawd v1 只有 Claude Code 一个来源，两枚独立的环更清楚。
> 同心双环有实打实的可读性代价（哪圈是哪个要学一遍），
> 只有在必须省空间时才值得付。

### 4.3 视觉规则：它浮在壁纸上，不在页面上

环身后没有任何表面，所以常规的主题 token 全部失效：

1. **不画卡片背景。** 加个半透明圆角矩形会让它看起来像个误入桌面的网页组件。
2. **可读性靠两样东西**：环的 `drop-shadow`，和文字的**字幕式描边**
   （`0 1px 2px rgba(0,0,0,.85)` 一类）。这是字幕在任意画面上保持可读的老办法。
3. **颜色是固定物理值，不跟随明暗主题。** 身后是用户的壁纸，不是我们的页面，
   系统主题跟这里没关系。

### 4.4 电池隐喻：显示剩余，不显示已用

**环从满到空，像电池。**

这不是措辞偏好，是两件事：

- 电池是所有人都有的心智模型：满 = 好，空 = 该充电了。进度条是反的——
  填满意味着完成，而配额填满意味着完蛋。
- 「还剩 22%」和「用了 78%」是同一个数字，语气完全不同。价值观红线第 1 条
  要求不制造焦虑，这是最省力的一次兑现。

| 剩余 | 环色 | 行为 |
| --- | --- | --- |
| ≥ 40% | **不显示**（见 4.5） | — |
| 15–40% | 角色主色 `#DE886D` | 静止 |
| < 15% | 琥珀 | 缓慢呼吸；`prefers-reduced-motion` 下静止 |
| 已重置 / 未知 | 灰 | 不显示百分比 |

**不用红色。** 红色在 Maclawd 里已经是 `error` 状态的语言（菜单栏标记的
`systemRed`）。配额低不是错误，是正常的资源状态。

**健康档用角色主色而不是绿色。** 绿色是仪表盘语言。用 `#DE886D` 把环和角色
绑成一体，它才是「桌宠身边的东西」而不是「一个通用监控部件」。

### 4.5 显隐：按需浮现

这是环最重要的一条产品决定。

| 剩余 | 默认行为 |
| --- | --- |
| ≥ 40% | **不显示** |
| < 40% | 显示 |
| 悬停桌宠 | 无条件显示（想看随时能看） |

**没消息就是好消息。** 常显是持续的视觉噪音；只在悬停时显示又损失了「零点击」
这个全部价值。按需浮现两头都占：正常状态下你根本看不见它，
只有真的快用完了它才出现——而那一刻你确实需要知道。

三档用户设置：`按需浮现（默认）/ 常显 / 关闭`。

**热区续命。** 桌宠命中框与环矩形的并集，加 12pt padding。鼠标在这个并集里，
环就保持可见；离开后 400ms 淡出。没有这条，鼠标从桌宠移向环的路上环就消失了。

### 4.6 配额与 energy 必须解耦

`energy` 由**当日 throughput ÷ 个人 14 天中位数**决定，配额由**账号窗口**决定。
两者**不接**。

理由是价值观而不是工程：energy 的语气是「陪你一起累」——温和、个人化、
按你自己的基线；配额是硬事实。把角色的困倦接到配额上，就变成了
**用角色向用户施加压力**，同时踩中红线第 1 条（不制造焦虑）和第 3 条
（高用量不做负面表演）。

**配额低不改变角色的任何表演，不触发任何通知。环变色是唯一的表达。**

## 五、popover（P1）

### 5.1 popover 是什么，以及为什么选它

`NSPopover` 是 AppKit 的瞬时锚定面板：挂在某个视图上，带指向锚点的箭头，
点外面自动消失。

| | NSMenu（现状） | **NSPopover** | 无边框 NSPanel |
| --- | --- | --- | --- |
| 能放什么 | 只能是菜单项 | 任意视图 | 任意视图 |
| 箭头锚定 / 点外消失 / 毛玻璃 | 部分 | **全部免费** | 全部自己写 |
| 会不会抢当前应用焦点 | 不会 | **会** | 可以不抢 |
| 代码量 | — | **~40 行** | ~200 行 |

**v1 选 NSPopover。** 两个前提已确认：`main.swift` 用的是 `.accessory` 策略，
激活不会顶掉别人的菜单栏；面板里不需要文本输入，也不需要长驻。
抢焦点是唯一代价——在编辑器里打字时点开面板，输入焦点会丢。

**什么时候换 NSPanel**：想要「钉住面板边看边工作」，或者想让双击桌宠时面板
贴着桌宠浮出来而不打断输入。**把内容层和容器层分开写，换容器是一天的事。**

### 5.2 内容

```
┌──────────────────────────────────────┐
│                                      │
│           [ 角色 96px ]               │
│                                      │
│         正在整理工作牌                 │
│         12.4K/min  ▓▓▓▓▓▓░░░░        │
├──────────────────────────────────────┤
│  5 小时   ◔  还剩 22%   2h14m 后重置  │  ← 配额在前
│  本周     ◕  还剩 41%   周日重置      │
├──────────────────────────────────────┤
│  今日  1.24M 计费 tokens              │  ← 计数在后
│  比平时多 18%                          │
│  ▁▁▁▂▃▅▇▆▃▂▁▁▁▁▁▁▂▄▅▃▁▁▁            │
├──────────────────────────────────────┤
│  Maclawd            820K             │
│  vibe-usage         380K             │
│  其他 3 个            40K             │
├──────────────────────────────────────┤
│  缓存 78% · 活跃 3h12m · 连续 12 天    │
├──────────────────────────────────────┤
│  今天 ▾        完整统计 ↗       ⚙     │
└──────────────────────────────────────┘
```

360pt 宽，**高度 ≤ 460pt，不允许出现滚动条**。滚动条出现的那一刻就说明内容选错了，
该砍内容而不是加滚动。

五条设计要点：

1. **第一屏必须是角色，不是数字。** 这是 Maclawd 与其他用量工具唯一的结构性差异。
   打开先看到大数字，产品就退化成「多了个宠物图标的 tokei」。
   角色占视觉重心不是装饰，是定位的物理体现。
2. **角色下面那行文案是这块面板真正的独家价值。** 「正在整理工作牌」回答的是
   **「它在干什么」**，不是「用了多少」。别的用量工具给不了这个，因为它们没有状态引擎。
   这一行比下面所有数字加起来更值钱。
3. **配额在计数前面。** 理由见第零节。
4. **计数只显示一个口径。** 计费与吞吐并排会让人以为其中一个是错的。
   默认计费，悬停出 tooltip 显示吞吐与差额（`usage.html:238` 已有实现，复用）。
5. **成本默认不进 popover。** 菜单栏密度档里保留「今日成本」没问题——**那是用户
   主动选的**；popover 是一天要瞥几十次的表面，把钱摆在那里等于每天几十次的
   焦虑推送。**主动查询 ≠ 被动灌输。** 成本留在展开态和 `/usage`。

**明确不放**：筛选器、模型表、30 天热力图、覆盖率、任何设置项本身。
齿轮是**跳转**，不是在 popover 里开二级面板——弹窗里套弹窗是公认的坏模式。

### 5.3 技术形态：混合渲染

| 区域 | 渲染方式 | 理由 |
| --- | --- | --- |
| 角色台头 | WKWebView | CSS/SVG 零转换是整个架构的赌注，不能破 |
| 其余全部 | 原生 AppKit | 暗色、毛玻璃、系统字体、VoiceOver 全部免费 |

两个支撑这个选择的事实：

- **数据管道已经现成。** `RuntimeClient.swift:249` 已经在每 2 秒轮询
  `/api/summary?range=today`，`UsageSnapshot` 里 billable / throughput / cost /
  hitRate / activeSeconds 全解析好了。缺的 baseline、byProject、hours[24]
  **`/api/summary` 本来就在返回**（`usage.html` 用的就是这几个字段）。
  **后端一行不用改**，只要给 `UsageSnapshot` 加字段解析。
- **走纯网页反而更贵。** `usage.html:9` 硬编码了 `color-scheme:light`。
  菜单栏面板不支持暗色是「这不是个真 Mac 应用」最刺眼的信号，
  而给那一整页补暗色的工作量不比把几块数字写成原生小。

代价是排版有两份实现会漂移——但漂移的是**排版**不是**数值**，
数值同源于 `/api/summary`。可以接受。

### 5.4 六个会真咬人的坑

1. **WKWebView 默认画不透明白底。** 不关掉 `drawsBackground`，毛玻璃里会嵌一块
   死白方块，看起来像渲染失败。
2. **暗色下的角色。** `#DE886D` 在深色底上可能需要提亮，要实机确认。
3. **冷启动闪白。** WKWebView 首次加载 200–400ms，必须在应用启动时就建好预热藏着；
   点击时才建会看到「先空一下再蹦出内容」。
4. **面板关着时 CSS 动画还在跑。** 持续耗电，关闭时要主动 pause。
5. **降级态不能显示 0。** `0 tokens` 的意思是「今天没用」，而实际是「没测到」——
   **这是撒谎**。三种降级态各自诚实（见 5.5）。
6. **折叠/展开要动画改 contentSize。** 直接赋值会「啪」地跳一下。

### 5.5 三种降级态

角色照常 idle，**不消失、不显示错误图标**。没数据不是故障。

| 情况 | 文案 | 动作 |
| --- | --- | --- |
| 运行时没起来 | 「运行时没有启动」+ `lastError` | 提供「重试」 |
| 用量记录被关 | 「用量记录已关闭」 | 提供「重新开启」，**不显示任何历史数字** |
| 从未检测到日志 | 「还没有找到用量记录」 | 说明会自动开始记录 |

关闭态不显示历史数字，即使数据还在盘上——用户关掉的是「记录这件事」，
继续展示旧数字会让人觉得开关没生效。重开后数字立刻回来（`rollup.json` 是派生数据）。

## 八、验收标准

写在前面，不然做完只能靠「感觉还行」判断：

1. 打开面板到读懂「现在在干嘛」< 1 秒
2. 面板不出现滚动条
3. 冷启动到内容可见 < 150ms
4. 配额环在剩余 ≥ 40% 时**看不见**
5. 关闭用量记录后，面板不显示任何历史数字
6. 卸载配额开关后，`~/.claude/settings.json` **逐字节回到接管前的状态**
7. 用户原有的状态行在任何情况下都没被弄坏

第 6、7 条要有测试。安装与卸载不对称是这类功能最容易出、也最伤信任的 bug。

## 九、价值观红线（更新版）

前六条继承 `token-experience.md`：

1. 不制造焦虑。不用「你花了多少钱而你不知道」的叙事。
2. 不在角色**身上**贴任何数字、进度条、百分比、徽章。
3. 高用量不做负面表演。累了就是困，困是可爱的。
4. 无数据时角色不消失。
5. 不把角色变成图表的一部分。
6. 成本永远标注为「估算」。

新增三条：

7. **配额显示剩余，不显示已用。** 电池隐喻，不是进度条。
8. **配额不接 energy。** 角色的困倦只由当日 throughput 与个人基线决定。
9. **配额低不触发任何通知、不改变角色的任何表演。** 环变色是唯一的表达。

第 2 条与配额环不冲突：环在角色**旁边**，不在角色身上。这个区分是刻意的。
