# Maclawd 前端方案 v1

状态：**已实现并在真机数据上验证**。数据层见 [`token-tracking.md`](token-tracking.md)，
产品与视觉决策见 [`token-experience.md`](token-experience.md)。

## 两个页面，两种职责

| 页面 | 路径 | 回答的问题 |
| --- | --- | --- |
| **宠物管理** | `/` | 这只桌宠有哪些状态？现在什么感受？我要怎么配它？ |
| **用量统计** | `/usage` | 我花了多少？花在哪？和平时比呢？ |

刻意分开而不是做成一个带 tab 的页面：两者的使用节奏完全不同。宠物管理是**偶尔进来
调一次**，用量统计是**每天瞥一眼**。合并会让高频页面被低频配置项挤满。

## 架构：零依赖本地服务 + 无构建 HTML

```
bin/maclawd-usage serve   →  src/runtime/server.js (node:http, 只绑 127.0.0.1)
                              ├── web/pet.html      宠物管理
                              ├── web/usage.html    用量统计
                              └── /api/*            JSON
```

为什么要一层服务而不是直接双击打开 HTML：浏览器读不到
`~/Library/Application Support/Maclawd/rollup.json`。服务层只做两件事——把聚合数据
暴露成 JSON、把仓库里的 SVG 提供给页面，**不引入任何构建步骤**，页面仍然是可以直接
阅读的单文件 HTML。这保持了仓库既有的「无构建」传统，也让将来的 Swift 外壳可以直接
复用同一套页面（WKWebView），或照此重写原生界面。

零依赖：`node:http` + `node:fs`，没有框架、没有打包器、没有 CSS 预处理。

## 从两个参考项目各取什么

### 取自 vibecafe.ai/usage

**1. 多维联动筛选（工具 × 模型 × 项目）。**
这是它最实质的能力，也是本项目为此**重构了聚合结构**的原因：原来按模型和按项目
分两张表存，只能单独看某一维；改成存 (模型 × 项目) 的交叉单元后，才能回答
「模型 A 在项目 B 上花了多少」。代价是单元数从 (模型+项目) 变成 (模型×项目)，
实测 113 天约 1MB，可以接受。

**2. 覆盖率指标。**
「能精确计价的 token 占比」。这比「有 X token 未计价」好读得多，也更容易一眼看出
价格表缺口有多大。

这个指标随后直接推动了一个决定：面板上「更新价格表」按钮。实测拉取 OpenRouter
后覆盖率从 **10% 提到 97.8%**，成本从 $3020 修正为 $9789——覆盖率把「成本那栏只
反映了一成用量」这件事摆到了台面上，否则会一直藏在一个看起来精确的总额后面。

**没取：排行榜。** 需要云端与账号，与「纯本地」原则冲突（见
`token-tracking.md` 不可变原则 1）。

### 取自 tokei

**1. 项目足迹带打开入口。** 项目列表每行有 Finder / VS Code / 终端三个按钮，
把面板从「只能看」变成「工作入口」。这要求存项目的**完整路径**而不只是 basename，
所以数据层补了 `projectPaths`。
安全上：只接受白名单动作，且路径必须**恰好等于** rollup 里记录过的项目路径，
前端传什么都不直接执行。

**2. 周热力图。** 纵轴周一至周日、横轴按周展开，用透明度表达强度。
比折线更容易看出作息规律。

**3. Wrapped 式回顾。** 活跃天数、连续活跃、高峰时段、本命模型、主战场、起始日。
纯派生，不需要额外存储。

**4. 模型行展开明细。** 点击模型行展开输入/输出/缓存读写/推理/吞吐。
默认收起，需要时再看。

**没取：额度轨迹。** 需要读 Claude Desktop 的 Chromium HTTP 缓存，实现脆弱且
随时会被上游改坏，与主线正交（见 `token-tracking.md` 范围外）。

### Maclawd 独有

**角色台头。** 两个页面顶部都是角色，而不是图表。角色播放真实动作，
下面一行是该动作已有的中文「一眼读法」文案 + 实时速率。用户瞥一眼就知道
「它在干什么」，比任何数字都快。文案在角色**下方**，不在身上——
主状态契约第 6 条禁止动画内出现文字。

**双口径并存。** 主数字口径可切（计费量 / 吞吐量），悬停显示两者与差额。
实测两者可差 20 倍以上，任何对外数字都必须标注口径。

**体力条只在诊断页。** 宠物管理页显示 energy 是为了调试；产品面板里它只通过
角色行为体现——画成进度条会把「陪伴」降级成「指标」。

## API 契约

| 端点 | 方法 | 说明 |
| --- | --- | --- |
| `/api/summary?range&source&model&project` | GET | 聚合摘要 + 会话 + 覆盖率 + 基线 + 维度 + Wrapped |
| `/api/live` | GET | `tokensPerMin` + 强度 + 新增记录数 |
| `/api/actions` | GET | 38 个动作 + 角色几何合同 |
| `/api/tools` | GET | 各工具是否安装及数据目录 |
| `/api/settings` | GET / POST | 设置读写，POST 只接受已知键 |
| `/api/scan` | POST | 触发全量扫描并重建聚合 |
| `/api/open` | POST | 在 Finder / 编辑器 / 终端打开项目（白名单 + 路径校验） |
| `/api/update-prices` | POST | 联网更新价格表（唯一对外请求，用户显式触发） |
| `/api/state` | GET | 当前运行时状态 + 播放计划 + 体力/阈值诊断 |
| `/api/event` | POST | 投递 hook 事件（现由面板手动触发以验证状态机） |
| `/api/status` | GET | 后台采集循环状态 |
| `/api/reset` | POST | 删除派生数据，本机日志不受影响 |

**版本守卫**：聚合结构版本不匹配时 `/api/summary` 返回 `{empty, stale}`，
前端明确提示需要重新扫描，而不是硬着头皮解析出一片 0——
「显示 0」和「没有数据」在用户眼里是同一回事，会被当成 bug。

## 宠物管理页构成

1. **预览台** — 大图 + 96px / 64px / **22px 菜单栏**三档同时对照
2. **动作清单** — 38 个动作按主状态 / 工作修饰 / 互动环境 / 生命周期分组，点击预览
3. **状态链演示** — 一键播放 `away → sleeping → waking` 等五条链，验证转场是否连续
4. **感知与体力** — 实时强度条 + energy 条，标注公式
5. **设置** — 五个开关 + 主口径选择，每项都写清代价
6. **工具检测** — 六款工具的安装状态与数据目录
7. **危险区** — 删除全部用量记录，二次确认

22px 那一档是刻意加的：菜单栏实际就是这个尺寸，而现有 QA 只覆盖 64/96px。
页面上直接把三档并排，一眼就能看出 22px 基本不可读——这是
`token-experience.md` 待决事项 1 的可视化证据。

## 用量统计页构成

1. **角色台头** + 实时速率
2. **7 档区间** + 三个维度下拉 + 清除筛选
3. **主数字** + 比平时 + 成本 + 覆盖率 + 命中率 + 活跃时长 + 五字段明细
4. **作息分布**（筛选时明确标记不可用，而不是给出错误分布）
5. **每日趋势**（最近 60 天柱状）
6. **活跃热力**（周 × 星期）
7. **按工具 / 按模型**（可展开明细）
8. **项目足迹**（带打开入口，点项目名即筛选）
9. **回顾**

## 一处诚实的降级

筛选状态下**作息分布不可用**。预聚合的 `hours[24]` 是跨来源汇总的，按筛选条件
拆不出来。这时前端隐藏图表并说明原因，而不是给出一个看起来合理但错误的分布。
要支持筛选后的作息，得把 hours 也存进交叉单元，那会让聚合体积再涨 24 倍——
不值得。
